# Kafka Configuration & Topic Mapping Registry

This document provides a comprehensive specification of all Apache Kafka topics in the trading platform, their event schemas, and a matrix mapping component roles (**Producer** vs **Consumer**).

---

## 1. Master Kafka Topics Specification

### 1. `trading-signals`
- **Config Property**: `trading.topics.signals` (Java) / `KAFKA_TOPIC_SIGNALS` (Python)
- **Default Name**: `trading-signals`
- **Primary Producer**: `signal-gen` (`signal_publisher.py`)
- **Primary Consumer**: `ops` (`SignalConsumer.java`, Consumer Group: `ops-group`)
- **Key**: Ticker symbol (e.g. `"AAPL"`, `"MSFT"`)
- **Purpose**: Carries raw quantitative trading signals generated by strategy modules to the Pre-Trade Risk Engine (OPS) for risk checks and margin locking.
- **Event Payload Schema (JSON)**:
  ```json
  {
    "symbol": "AAPL",
    "action": "BUY",
    "qty": 15,
    "price": 224.50,
    "provider": "alpaca",
    "strategy": "SmaCrossover"
  }
  ```

---

### 2. `order-create-events`
- **Config Property**: `trading.topics.order-create` (Java) / `TOPIC_ORDER_CREATE` (Python)
- **Default Name**: `order-create-events`
- **Primary Producer**: `ops` (`SignalConsumer.java`)
- **Primary Consumers**:
  - `oms` (`OrderCreateConsumer.java`, Consumer Group: `oms-group`)
  - `notification svc` (`NotificationConsumer.py`, Consumer Group: `notification-service-group` - optional filter)
- **Key**: `orderId`
- **Purpose**: Dispatched by OPS when a trading signal passes all pre-trade risk firewall gates and is submitted to the broker gRPC connection manager. Triggers OMS to insert a new `PENDING` order record in PostgreSQL.
- **Event Payload Schema (JSON)**:
  ```json
  {
    "orderId": "ord-8f92a1b4-2026",
    "symbol": "AAPL",
    "qty": 15,
    "side": "BUY",
    "orderType": "MARKET",
    "limitPrice": 224.50,
    "provider": "alpaca",
    "strategy": "SmaCrossover"
  }
  ```

---

### 3. `order-reject-events`
- **Config Property**: `trading.topics.order-reject` (Java) / `TOPIC_ORDER_REJECT` (Python)
- **Default Name**: `order-reject-events`
- **Primary Producer**: `ops` (`SignalConsumer.java`)
- **Primary Consumer**: `notification svc` (`NotificationConsumer.py`, Consumer Group: `notification-service-group`)
- **Key**: `orderId`
- **Purpose**: Dispatched by OPS when a signal is rejected by risk rules (e.g., daily loss breach, price collar violation, velocity limit) or broker gRPC transport errors. Triggers multi-channel alerts (Telegram, ntfy, WhatsApp).
- **Event Payload Schema (JSON)**:
  ```json
  {
    "orderId": "ord-rej-9912a",
    "symbol": "MSFT",
    "qty": 100,
    "side": "BUY",
    "price": 520.00,
    "estimatedCost": 52000.00,
    "provider": "alpaca",
    "strategy": "MeanReversion",
    "rejectReason": "MAX_CONCENTRATION_EXCEEDED",
    "riskGateLevel": "PORTFOLIO_CONCENTRATION",
    "timestamp": 1789237740000
  }
  ```

---

### 4. `raw-order-updates`
- **Config Property**: `trading.topics.raw-updates` (Java) / `KAFKA_TOPIC_RAW_ORDER_UPDATES` (Python)
- **Default Name**: `raw-order-updates`
- **Primary Producer**: `conn-mgr` (`kafka_publisher.py` in `connection-manager-alpaca`)
- **Primary Consumer**: `oms` (`OrderUpdateConsumer.java`, Consumer Group: `oms-group`)
- **Key**: Alpaca Order ID or Client Order ID
- **Purpose**: Forwards raw execution and order status stream updates received from Alpaca WebSocket (`TradingStream`) directly to Kafka for downstream consumption by OMS.
- **Event Payload Schema (JSON)**:
  ```json
  {
    "event": "fill",
    "price": 224.50,
    "qty": 15,
    "position_qty": 15,
    "timestamp": "2026-09-12T23:49:25Z",
    "execution_id": "exec-7712a",
    "order": {
      "id": "alpaca-ord-12345",
      "client_order_id": "ord-8f92a1b4-2026",
      "symbol": "AAPL",
      "side": "buy",
      "qty": 15,
      "filled_qty": 15,
      "filled_avg_price": 224.50,
      "status": "filled",
      "order_type": "market",
      "time_in_force": "day"
    }
  }
  ```

---

### 5. `order-complete-events`
- **Config Property**: `trading.topics.order-complete` (Java) / `TOPIC_ORDER_COMPLETE` (Python)
- **Default Name**: `order-complete-events`
- **Primary Producer**: `oms` (`OrderResolutionService.java`)
- **Primary Consumer**: `notification svc` (`NotificationConsumer.py`, Consumer Group: `notification-service-group`)
- **Key**: `orderId`
- **Purpose**: Emitted by OMS when an order reaches terminal resolution (`COMPLETED` or `FAILED`), following PostgreSQL database settlement and Redis balance/position updates.
- **Event Payload Schema (JSON)**:
  ```json
  {
    "orderId": "ord-8f92a1b4-2026",
    "symbol": "AAPL",
    "qty": 15,
    "side": "BUY",
    "status": "COMPLETED",
    "filledQty": 15,
    "filledAvgPrice": 224.50,
    "provider": "alpaca",
    "strategy": "SmaCrossover"
  }
  ```
